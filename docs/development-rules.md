# LOW KEY Development Rules

## Código

- Preferir TypeScript.
- Mantener código limpio.
- Evitar duplicación.
- Crear componentes reutilizables.
- Utilizar nombres descriptivos.
- Mantener funciones pequeñas.
- No agregar dependencias innecesarias.

## Seguridad

- Nunca guardar secretos en Git.
- Utilizar variables de entorno.
- No subir archivos .env.
- Validar entradas del usuario.

## Testing

Las funcionalidades importantes deben tener pruebas.

La herramienta principal será Playwright para testing
end-to-end.

## Git

Utilizar commits descriptivos.

Ejemplos:

feat: add landing page

fix: resolve login issue

refactor: improve authentication service

docs: update project documentation
